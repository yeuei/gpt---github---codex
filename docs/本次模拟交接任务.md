# 本次模拟交接任务

## 1. 任务目的

本项目要验证一条可持续运行的本地协作链路：

```text
本地 Codex Agent
  → GitHub 交接仓库
  → 固定 ChatGPT Web 对话
  → GitHub 交接仓库
  → 本地 Codex Agent
```

触发器是本机确定性程序，不让 LLM 决定网页点击路径。ChatGPT 负责 GitHub 侧的任务协调和 PR 生命周期；本地 Agent 负责代码实现、测试、运行证据和问题修复；用户保留每条浏览器消息的最终发送权。

## 2. 本次首个可关闭目标

**完成本地 GitHub ↔ ChatGPT Web 触发器 V1 的审批式模拟交接，并记录可复现的运行证据。**

范围包括：

1. 触发器监听带 `Coordination-*` trailer 的 Git 提交，按 event id 去重并记录时间线；
2. Dashboard 支持总开关、两个方向独立开关、逐条审批和按 PR 查看事件；
3. `Agent → ChatGPT Web` 使用固定 OBU CLI 流程，默认只填入不自动发送；
4. Dashboard 显示 OBU 连接状态，支持手动连接检测、失效 registry 清理和有限重试；
5. `ChatGPT Web → Agent` 仅在用户明确配置本地命令后启动，不猜测命令；
6. 真实 PR 建立后，实例化对应的 `coordination/PR-<真实编号>/` 三文件并完成至少一轮双向事件记录；
7. 把断线、假成功、权限和回环问题写入 `docs/触发器问题与解决方案.md`，再批量同步到三份基础协议仓库。

## 3. 验收顺序

1. 当前分支说明和项目事实已写入本仓库并推送；
2. 创建一个只服务本目标的真实 PR；
3. 从真实 PR 编号实例化 `任务.md`、`agent汇报.md`、`chatgpt解惑.md`；
4. 本地 Agent-origin 提交进入 Dashboard 的待审批队列；
5. 用户批准后，固定 ChatGPT Web 对话出现唤醒草稿；用户手动发送；
6. remote ChatGPT 重新读取 GitHub 当前状态并创建/更新真实 PR；
7. ChatGPT-origin 更新重新进入本地待审批队列；批准后启动已配置的 Agent 命令；
8. 核对 Git 历史、SQLite 时间线、PR 文件和问题文档，没有重复事件或虚构 PR 号。
