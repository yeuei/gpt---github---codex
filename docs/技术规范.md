# 技术规范

> 本文件是项目当前技术实现的主真源之一。
> 当前仓库尚未绑定具体业务/科研目标，因此本文件只记录初始化状态，不虚构技术方案。
> 后续产生正式技术规范时直接原位更新本文件；历史通过 Git commit 查看。

## 1. 当前总流程

```text
用户定义正式项目目标
  ↓
ChatGPT 将目标拆成可关闭 PR 总任务与子任务
  ↓
Codex Agent 在本地实现 / 运行 / 验证
  ↓
Agent 更新 agent汇报.md 与任务状态
  ↓
ChatGPT 解决 blocker / 更新 chatgpt解惑.md
  ↓
达到验收条件后完成 PR
```

## 5. 运行与恢复

尚未绑定具体 runtime。

未来普通工程实现（日志、progress、checkpoint、resume、failure handling）默认由 Agent 自行设计为可复现方案，无需为这些细节等待用户。

## 6. 验收条件

对任何正式 PR：

```text
代码存在 ≠ DONE
smoke 通过 ≠ formal DONE
```

只有当 `coordination/PR-<N>/任务.md` 中全部仍有效任务完成、无 BLOCKED / WAITING_USER，且代码/运行证据支持完成状态时，才可把总任务标为 `[x]`。

## 7. 禁止事项

- 不得用旧 runner 的行为反推当前规范；
- 不得用历史 smoke 替代正式运行；
- 不得把聊天记忆冒充 GitHub 当前事实；
- 不得因为局部 blocker 停止互不依赖任务；
- 不得无理由新增 smoke / benchmark / audit 延迟主线；
- 不得为保存历史创建 `技术规范_v2.md`、`final.md`、`latest.md` 等平行版本。

## 8. 版本更新原则

正式规范变化时：

```text
直接修改 docs/技术规范.md
```

Git commit 保存变化历史，HEAD 仅表达当前有效方案。
