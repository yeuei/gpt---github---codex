# 触发器问题与解决方案

> 只保留当前有效问题与解决方案；PR #1/V1 的详细排障过程由 Git 历史保存。

## P1：后台自动 fetch 让 Dashboard 依赖网络

- 当前结论：已由 local-first 架构取代。
- 方案：后台 `scan_local()` 只读取本地 refs/history；网络同步只能通过“从 GitHub 刷新”或 `--refresh-once`。
- 失败语义：fetch 失败保留当前事件/审批/投递状态并显示准确错误。

## P2：历史节点被当前任务或时间近似污染

- 当前结论：只允许 exact commit SHA。
- 方案：节点调用 `git show <sha>:coordination/PR-N/任务.md`。
- 缺失语义：明确 `历史任务快照不可用`，不按事件时间匹配，不回退当前 `任务.md`。

## P3：单一 status 混合审批与发送结果

- 当前结论：拆成 `approval_state` 与 `delivery_state`；GitHub PR state 是第三个独立来源。
- 旧数据：无法可靠拆分时显示 `legacy_unknown`，不猜测。

## P4：Dashboard 多层 renderer 持续叠加

- 当前结论：当前 UI 只有 `trigger/dashboard.html` 一套 renderer。
- 统一范围：筛选、canvas、节点点击、拖动/缩放、详情、任务快照与配对入口都由同一前端 state 管理。

## P5：Trigger 审批与 Codex 命令审批容易混淆

- 当前结论：两者保持独立。
- Trigger 审批决定是否路由一个协作事件；Codex app-server `on-request` 决定具体 shell/file 操作。

## P6：配对 token 不能由 ChatGPT 伪造或进入日志

- 当前结论：本机 `/pair` 调用真实 `/api/bindings/invite`。
- 分享链接只把 token 放入 URL fragment；Local Agent 之后执行 claim → confirm。
