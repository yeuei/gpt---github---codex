# 项目总览

## 项目目标

`gpt---github---codex` 是 `CodexWithEveryLlm` 协议的一份真实交接实例，同时承载本机 Dashboard/runtime。
当前主线是把 Dashboard 从“后台实时 fetch + 多层 renderer + 状态混用”重构为**本地 Git 优先、历史可核验、状态分层、单 renderer**的实现。

## 当前不变量

1. Git 历史不可改写；HEAD 只保留当前有效事实。
2. 只有真实开放 PR 才在 HEAD 保留 `coordination/PR-N/`。
3. Dashboard 后台默认只读取本地 Git 与 SQLite。
4. 网络刷新必须由用户显式触发，失败不能破坏当前本地展示状态。
5. 节点任务状态必须来自节点 commit SHA 对应的 `任务.md`。
6. 历史快照缺失就显示不可用，绝不回退到当前任务或按时间近似。
7. Trigger 审批、投递/发送、GitHub PR 状态严格分离。
8. Trigger 自动审批与 Codex shell/file approval 严格分离。
9. Dashboard 只有一套当前 renderer 和一套筛选/点击/拖动/详情状态模型。

## 当前主线

```text
本地 Git refs/history ──后台扫描──> SQLite event audit ──> Dashboard
       │
       └── 用户点击“从 GitHub 刷新” ──> git fetch ──> 再做本地扫描

事件节点 ── commit SHA ──> git show SHA:coordination/PR-N/任务.md
```

## 验收口径

- 单元测试覆盖本地优先、刷新失败、exact-SHA 快照、状态分离、单 renderer、binding；
- Python 编译、Dashboard JavaScript 静态语法检查、`git diff --check` 均可由 GitHub Actions 复现；
- GitHub PR diff 能清晰对应每条协议要求；
- 本机真实 Dashboard/browser 运行若需要再次验收，必须由 Local Agent 在用户机器上执行，不用 CI 冒充本地运行证据。
