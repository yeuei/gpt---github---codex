# 项目总览

## 项目目标

`gpt---github---codex` 是 `CodexWithEveryLlm` 协议的一份真实交接实例，同时承载本机 Dashboard/runtime。

当前已经形成两条连续主线：

1. PR #3 完成 Dashboard 的 local-first、exact-SHA、状态分层与 single-renderer 重构；
2. PR #4 在此基础上增加受控人工操作，让用户可以从流程节点向配对 GPT 发起修改请求，并在显式 GitHub 刷新后看到对应的新 GPT 节点。

## 当前阶段

- PR #1 已完成 V1 双向模拟交接并合并到 `main`。
- PR #2 是独立的配对链接工作，仍按其真实 GitHub 状态存在。
- PR #3 是 local-first Dashboard 重构 PR，真实开放，branch 为 `refactor/local-git-dashboard`，当前业务任务已经完成。
- PR #4 是新的 Dashboard 节点人工操作 PR，真实开放，branch 为 `feature/dashboard-node-gpt-actions`。
- PR #4 当前以 `refactor/local-git-dashboard` 为 stacked base，避免把 PR #3 的大规模重构 diff 重复计入本功能 PR；PR #3 合并后再 retarget 到 `main`。
- PR #4 当前只完成技术规划与任务初始化，尚无 Local Agent 本机实现或真实 E2E 证据。

## PR #4 当前目标（PR #4 Current Goal）

```text
选中 Dashboard 节点
→ 右键“请求 GPT 修改”
→ 输入自然语言修改意见
→ Trigger 创建并审计本地 dashboard action
→ active binding 投递到配对 GPT Web conversation
→ GPT 重新读取 GitHub 当前 PR/HEAD 后修改当前 head
→ 用户显式点击“从 GitHub 刷新”
→ Dashboard 显示新的 GPT 节点并关联原用户 action
```

历史节点只作上下文，不允许用户 action 或 GPT 回写/改写旧 commit。

## 当前不变量

1. Git 历史不可改写；HEAD 只保留当前有效事实。
2. 只有真实开放 PR 才在 HEAD 保留 `coordination/PR-N/`。
3. Dashboard 后台默认只读取本地 Git 与 SQLite。
4. 网络刷新必须由用户显式触发，失败不能破坏当前本地展示状态。
5. 节点任务状态必须来自节点 commit SHA 对应的 `任务.md`。
6. 历史快照缺失就显示不可用，绝不回退到当前任务或按时间近似。
7. Trigger 审批、投递/发送、GitHub PR 状态严格分离。
8. Trigger 自动审批与 Codex shell/file approval 严格分离。
9. Dashboard 只有一套当前 renderer 和一套筛选/点击/拖动/详情状态模型。
10. Dashboard action 不直接修改 Git/GitHub，不自动 fetch，不自动 merge。
11. Dashboard → GPT 默认复用 Trigger + active binding；Codex CLI 不作为强制中转层。
12. PR/commit/主要变更标题采用 `中文标题（English technical title）`。

## 当前主线

```text
本地 Git refs/history ──后台扫描──> SQLite event audit ──> Dashboard
       │                                               │
       │                                               └─ 右键节点 → dashboard action
       │                                                                ↓
       │                                                        active binding → GPT
       │                                                                ↓
       └── 用户点击“从 GitHub 刷新” <── GitHub 新 commit/event <── GPT 当前 HEAD 修改
```

## PR #4 验收口径（PR #4 Acceptance）

- 右键节点可以发起 `request_gpt_revision`；
- action API 必须验证真实 event / PR / SHA；
- 无 active binding 时明确 `needs_binding`；
- active binding 时 GPT 配对对话收到真实请求；
- action 本身不执行 GitHub fetch、不修改 Git 工作树；
- 后续 GPT event 可通过 `dashboard-action:<id>` 建立因果关系；
- 原有 local-first / exact-SHA / single-renderer 行为不回归；
- 自动测试和 GitHub Actions 通过；
- Local Agent 必须提供一条真实本机 E2E，CI 不能冒充浏览器/配对/runtime 证据。
